## 01:24 — D-067 shipped: the path-guard is author-scoped (#295)

The ack is now required from every author except `AUTHORS_EXEMPT` (just `scolacur`), and never
skipped on a `robot/*` / `sortie/*` head branch whoever opened the PR. The denylist is unchanged —
this scopes *who* is gated, not *what* is sensitive. Rationale, alternatives and the fail-closed
argument are in `DECISIONS.md` **D-067** (amends D-047); don't re-derive them here.

Two implementation details that are easy to get wrong on a *required* check, both load-bearing:

- **Exemption is a green exit inside the step, not a job-level `if:`.** A skipped job reports a
  `skipped` conclusion, which is not the success branch protection expects.
- **The `robot/*` branch test is a backstop, not redundancy.** If the Robot's identity ever
  collapses onto Steve's PAT, author-matching alone would exempt every Robot PR *and keep reporting
  green*. The prefix check makes that failure loud.

## 00:50 — "Firewall" is now a pinned glossary term, and the DB layer is not one

PD-474's direction D was written up as a DB access layer / "firewall". It is **middleware** — a
widget can always open its own `better-sqlite3` handle, so the caller can decline to use it. The
only firewall in this system is the Robot's DB-blind uid (D-055), where a *uid* makes the boundary
unavoidable from outside the code. Renamed throughout PD-474 and added to PROJECT.md §9 with the
test to apply to any proposed control: **can the caller decline to use it?** If yes, it is
middleware, and calling it a firewall makes a later reader trust it for something it cannot do.

## Verifying a shipped fix found a bug inside it

The inline-comment fetch reads **one page**, and GitHub's list-review-comments endpoint defaults to
created-**ascending**. On a PR that gathered more than `per_page` inline comments across rework
rounds, page 1 would hold only the *oldest* — every one behind `lastHandoffAt` — and new feedback
would be truncated away **with no error**. PD-394's own failure mode by a different route.

Fixed in PR #300 (`d3f3866`): newest-first, path extracted to `inlineCommentsPath` and asserted in a
test *because two ordering params in a URL read as cosmetic* and would be a tempting cleanup.

Also worth keeping: the REST field mapping (`user.login` / `author_association` / `body` /
`created_at`) was checked against live GitHub data. A wrong field name there fails **silently** as
"no inline comments, ever" — indistinguishable from a working poll.

# 2026-08-06 (coverage session) — the number nobody had measured

Ran past midnight into 08-07. Started as "what's the test coverage?" and turned into a PR, because
the honest answer was **nobody knew: the repo had no coverage tooling at all.** `@vitest/coverage-v8`
was in no workspace and no CI step measured anything. Shipped the dependency + a `test:coverage`
script per workspace so the question is answerable by command, and filed **PD-484 — [Tooling] Measure
test coverage properly** for the parts that are more than a dependency.

## The baseline, so nobody has to re-measure it

`--coverage.all` over `src/**/*.ts` on `main` @ `276f2ba` — 1009 tests, 59 spec files, all green:
server **74.9%** lines, agent-worker **75.6%**, web **52.5%**, ≈71% overall.

Two things the percentage hides, and both are why PD-484 exists:

- **`.svelte` is entirely unmeasured — 76 components, zero instrumented.**
  `apps/web/vitest.config.ts` deliberately runs without the SvelteKit plugin chain, so nothing
  transforms a component and coverage never sees one. Web's number describes its 31 `.ts` modules
  only. Any repo-wide figure quoted today silently excludes the largest body of frontend code.
- **`--coverage.all` is not optional.** Without it v8 reports only files a test imported: server
  reads **86.5%** that way versus **74.9%** honest. Baked `all: true` into all three configs — a
  default that flatters by 12 points is worse than no number.

## A test file had never run once, and nothing could have told us

`apps/web/src/lib/acute-strategies-generator/utils.test.ts` — the repo's only `.test.ts`, while both
vitest configs are `include: ['src/**/*.spec.ts']`. Renamed to `.spec.ts`: **14 tests that had never
executed, all passing** (web 196 → 210). A green suite is not evidence a file is in it.

Its target `utils.ts` also has **no production importer** — the route components under
`routes/widgets/acute-strategies-generator/` don't use it, and that folder duplicates
`IdeaList.svelte` / `IdeaEditModal.svelte` with the `lib/` copies. Dead module *and* dead test; worth
a look when PD-443 swaps the generic components in.

Added the suffix rule as a comment in both configs — the mechanism is invisible from the file itself.
