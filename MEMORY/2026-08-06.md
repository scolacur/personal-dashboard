## The Robot's write token was dead, and only a real attempt found it

`ROBOT_GITHUB_TOKEN` returned **401** — found while trying to open a bot-authored PR to test PD-424,
not by any monitoring. Verified **on the NAS** to rule out the 2026-07-30 false alarm (that one was an
inline `# comment` read as part of the value; Compose strips those, ad-hoc greps do not).

The Robot's hand-off is verify → commit → **push** → **`gh pr create`**, and both of the last two use
this token — so the first Robot after resuming would have done all the work and 401'd at the end.
Classic PATs (`ghp_`) expire silently; the read token beside it is fine-grained and was fine.

Steve minted a new one; verified 200 + login `sortie-bot-55`, then proven end-to-end when it opened
PR #297. **Recreate the container (`docker-compose … up -d`), do NOT `docker restart`** — a restart
reuses the existing environment and keeps the dead value.

## PD-424 verified live — the exact success signature

The bridge cannot be tested with a PR Steve authored: GitHub forbids approving your own PR, so the
approval gate can never be satisfied. It only ever serves **bot-authored** PRs. Runbook now in
`docs/robot.md`, including the credential precheck.

PR #297, approved after CI was already green (the ordering that triggers the bug):

```

PR #297 mergeable=MERGEABLE reviewDecision=APPROVED others_pending=0 others_failed=0
PR #297: UNSTABLE is this bridge's own in-flight check (PD-424); every other check is green — attempting merge.

```

Merged by `app/github-actions`, no `--admin`. **Real rollup data also corrected the fix mid-build:**
the first version counted every run in `statusCheckRollup`, and a check that failed then re-ran green
appears twice — it would have refused a genuinely green PR, the same bug from the other side. Deduped
to latest-run-per-check.

## The stale-image trap — the worker's heartbeat `sha` lies about what code is running

Recreating the container for the token change brought it back **still running code older than
PD-467 / PD-470 / PD-463 / PD-432**. The agent-worker image is a build artifact; `up -d` recreates
from the *existing* image. Rebuild is a separate step.

The heartbeat `sha` reads reassuringly current because it reports the worker's **grounding checkout**
(which pulls on boot), not the image. The honest check is **`budget != null` on `/system-status`** —
and PR #298 moved `publishBudgetPolicy` above the pause gate precisely so that check works *while the
loop is still paused*, i.e. before the switch it is meant to de-risk.

## CI silently not running means your PR conflicts

Three events on PR #293 fired `path-guard` but never `ci`. Not a flake: the PR **conflicted with
main**, so GitHub could not build `refs/pull/N/merge` — and `pull_request`-triggered workflows do not
queue at all, while `pull_request_target` ones (path-guard) still run. **path-guard running alone is
the tell for a conflicting PR.**
