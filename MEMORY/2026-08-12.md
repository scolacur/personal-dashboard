## The weekly scan had no cron at all

`MEMORY/2026-08-06` records PD-471 as making the scan "fully automatic". That is true of the
**transport** — no API key, no pasting — and false of the **schedule**: `runScan` was reachable
only from `POST /scans`, and the BST widget had no `registerCron`. Nobody noticed for days because

directions.

## ⚠️ The crons run on UTC — still outstanding

The first automatic scan fired **09:00 UTC = 05:00 Eastern** on Mon 08-10. PD-439 specified
"09:00 local" and the container is UTC, so every schedule is four hours early. Harmless for the
scan, wrong for the drafter on the 15th. **Fix is a one-line `TZ=America/New_York` on the
container** — preferred over shifting the expressions, which would then disagree with the
`scheduleLabel` the Jobs page renders. Not done.

## Two "no-op" buttons that were both reporting failure off-screen

Neither was dead:

- **Copy** — `navigator.clipboard` **does not exist** on `http://192.168.68.50:8088`. The async
  Clipboard API is secure-context-only, so it threw on every click. This is not a permission
  anyone can grant; it stays absent until the box is served over HTTPS. Fell back to
  `document.execCommand('copy')`. Anything else on this dashboard reaching for `navigator.clipboard`
  has the same latent bug.
- **Edit template** — it set state and rendered the editor *after the entire collapsible*, below
  three long draft bodies, so nothing scrolled into view.

Both reported their failure in a panel-level error slot far above the button that caused it. **The
lesson is placement: feedback that renders where the user is not looking is indistinguishable from
no feedback.**

## 33 of 70 matches were Steve's own account

`u/holographicbboy` posts the same gear as his listings, so every item he was selling matched his
own comment — **47% of the readout**. Filtered in `matchComments` (covers every ingest path, not
just the scan) and purged **on every boot** rather than by a `migrate()` step, because the ignore
list is a constant that will grow and a migration marks itself done. Verified live: 70 → 37 rows.

Also confirmed, with tests it never had: **a dismissed match is never re-surfaced.** The unique
`(listing_id, comment_id)` index plus `ON CONFLICT DO NOTHING` means a re-scan inserts nothing and
never touches `dismissed_at` — load-bearing, since PD-471 deliberately re-scans the same two
threads every week.

## Layout work, and a regression I shipped blind

Page actions moved to the header, drafted posts into a modal, and the page is now tabbed
(Matches / Lists / More) with sale terms back in the flow — which let `--bst-terms-tab-height` and
the bottom padding the page reserved *to avoid its own overlay* both be deleted.

**PD-440's "Last scanned" line overflowed the collapsed widget card** and sliced the preview line

grid row. Fixed with `flex-shrink: 0` on the rows so an overflow can only ever cost a whole line —

survived review.

**There is no browser tooling in this session.** Every visual change went out verified by
arithmetic and unit tests only, and one of them was wrong. Say so explicitly in the PR each time —
and note the height model still does not fully explain the observed clipping.

## No generic tab component existed

Steve asked before I got far. The only precedent is the ticket detail page's `segbar`: route-local,
two hardcoded tabs, `role="tab"` with no `aria-controls`, no roving tabindex, no arrow keys, no
`role="tabpanel"` — and desktop-only, with a **separate sticky bottom nav** driving the same panes
on mobile. Built `$lib/Tabs.svelte` with the full pattern; it should absorb the segbar under
PD-453.

Placement was chosen from mocks rather than argued: **top is the only placement that keeps one
shape at every width**. Bottom had a concrete collision with the then-fixed sale-terms tab.

judged was how it lands in this app — with a desktop/phone toggle Steve could open on his phone,
which is the one thing this session could not otherwise evaluate. Private locations were
deliberately replaced with placeholders rather than published.
