## 16:30 — Turning the loop on is TWO flags, and the blocker was neither of them

`ROBOT_DISPATCH_ENABLED` was already `1`. The thing actually holding dispatch since 2026-07-30 was
the **DB** flag, `robot_state.dispatch_paused` — the env flag decides whether the loop *arms* at
boot, the DB flag whether an armed loop *dispatches*, and it is re-read every cycle.

`EVALUATOR_ENABLED=1` is the genuinely new one (PD-487 ships the Evaluator off by default).

**The pause and its reason are one field.** `setDispatchPaused(db, false)` writes NULL to
`robot_state.dispatch_paused`; a null value reads as *not paused, no reason*. There is no separate
"clear the stale reason" step — I said there was, repeatedly, having taken the phrasing from
PD-468's body without checking. Resume clears both in one write.

## 16:30 — `robot-refresh` had to deploy its own fix, and a stale shell function hid it

First `robot-refresh` after the merge rebuilt correctly but reported `buildSha: null`. Cause: the
helper is a **shell function snapshotted at login**, and the version passing `--build-arg BUILD_SHA`
only reached disk during that same run's `git pull`. `source ~/.profile` then re-run fixed it.

Worth keeping in mind whenever `pd-aliases.sh` changes: `type <fn> | grep <new-flag>` tells you
whether your shell has the current definition.
