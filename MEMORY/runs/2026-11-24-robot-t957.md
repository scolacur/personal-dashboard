# [Decisions] Visual check approve button says "Looks right, merge PR" when approving will merge it

**What shipped:** The Visual check approve button reads "Looks right, merge PR" when approving is
the last gate (Evaluator shipped the current head AND the matching auto-merge switch is on),
otherwise "Looks right". A new `mergesOnApprove` flag on `AwaitingVisualItem` is computed
server-side; after approving, the card shows "Approved, auto-merge will merge #N once checks pass"
until the PR merges. Label/message logic lives in `apps/web/src/lib/visual-check-logic.ts`.

**Worth remembering:**
- The server can't read GitHub repo variables, so `autoMergeOn()` in `visual-review.ts` mirrors
  `AUTO_MERGE_ROBOT`/`AUTO_MERGE_ALL` via env vars that MUST be kept in sync by hand (noted in a
  code comment). Robot PRs key off `AUTO_MERGE_ROBOT`, session PRs off `AUTO_MERGE_ALL`.
- `evaluatorShipped()` applies D-101's "ship from every lens": latest `robot_evaluated` verdict per
  lens for the current head (after the review boundary) must be `ship`, and ≥1 lens must exist.
- No existing spec used `toEqual` on a whole `AwaitingVisualItem`, so adding the required
  `mergesOnApprove` field broke nothing. The capture-state `toEqual` cases assert on `.capture`.
- This was a continuation; the prior run had all source changes done and only the specs remained.
