# [Habit Tracker] Sets: nested habits, derived done/progress, tick-all shortcut, set filter chips

**What shipped:** Sets (habits with children, any depth) for the Habit Tracker. Shared pure
derivations in `packages/shared/src/habits.ts` (`nodeDue`/`nodeDone`/`nodeProgress`/`projectHabitDay`/
`setStreak`), a parent-aware `moveItem` with cycle rejection + a `PUT /items/:id/move` route, a
subtree-cascading archive, set rows in the server Today view, a tree-rendering `TodayList` with
filter chips + per-device collapse + tick-all set checkbox, and a nested-drag Habits tab.

**Worth remembering:**
- Set-ness is **structural** (has children) — there is no stored flag. "Create a set" in the UI is
  just creating an item and dragging children into it; the schedule pill is hidden once an item has
  children. This is per the glossary/spec, not a new decision.
- The streak refactor extracted a generic `dailyStreak(dueOn, doneOn, today, floor)` from the
  existing days-of-week logic so sets reuse it over their *derived* due/done days. Existing streak
  tests pin the old behaviour — the extraction preserves it exactly.
- Split of authority: a set's **streak** is server-only (needs full history) and comes from the
  Today row; its **done/progress** are recomputed client-side from the optimistic `completedToday`
  set so ticking a child updates the parent instantly. Two node shapes exist for this reason —
  `HabitDayNode` (one day) and `HabitHistoryNode` (full history, for streak).
- `moveItem` renumbers the whole destination sibling group (the frontend sends the new order),
  mirroring the existing whole-list reorder pattern. Cycle check walks ancestors of the new parent.
- Native drag in the Habits tab uses pointer position within a row: top quarter = reorder before,
  bottom quarter = after, middle = nest into; plus a bottom "drop to move out of a set" zone.
