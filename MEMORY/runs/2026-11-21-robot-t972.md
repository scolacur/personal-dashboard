# [Auto-queue] Board: "Eligible" computed view + "Queue eligibility criteria" info modal

**What shipped:** The Task Tracker board gained an "Eligible" filter toggle (shows only the Backlog
tickets the auto-queue promoter would queue, verdict `eligible`, via the bulk
`/queue-eligibility` board endpoint), a green "✓ eligible" badge on eligible cards in any lane, a
capacity-wait note on cards in the view ("waiting — Review WIP 3 / 3"), and a "Queue eligibility
criteria" info link (shown at the top of the view) opening a definitions modal.

**Worth remembering:**
- The *backend* for all of this already existed (D-103 / PD-808 / PD-809): `autoQueueEligibility`,
  the `GET …/queue-eligibility` board endpoint (`listBacklogAutoQueueEligibility`), `AUTO_QUEUE_CRITERIA`,
  `AutoQueueBoardEligibility`. This ticket was almost entirely the web view + modal. The only shared/server
  change was adding `AUTO_QUEUE_CAPACITY_DEFS` (static id/label/description for the 4 capacity limbs) so the
  modal renders capacity limits from one source, and refactoring `computeAutoQueueCapacity`'s inline
  labels/descriptions to read from it — the same single-source pattern `AUTO_QUEUE_CRITERIA` already uses.
- "Eligible" is a **filter toggle**, not a virtual column. The ticket said "filter chip OR virtual column,
  whichever fits". The board already has 5 filters that empty lanes; a sixth on/off toggle fits that pattern
  and avoids reworking `TicketBoard`. When on, `showEpics` is forced false (Epics have no `eligible` verdict).
- `QueueEligibilityChecklist` grew a `definitions` mode: `data` is now optional and when `definitions` is set
  it renders `AUTO_QUEUE_CRITERIA` + `AUTO_QUEUE_CAPACITY_DEFS` as a plain label — description list (no ✓/✗,
  no verdict). The `$derived` view must guard `data ?` → null, and the data branch is `{:else if view}`.
- `capacityWaitFor` (in `queue-eligibility-view.ts`, tested) **skips** the board-wide `epic-in-flight` capacity
  row — that row is computed with no Epic in view per `AutoQueueBoardEligibility` — and judges it per-card from
  `epicInFlight[epicId]` against `AUTO_QUEUE_EPIC_IN_FLIGHT_LIMIT` instead.
- The visual fixture already seeds an eligible ticket ("Floating Pomodoro button" under an active Epic), so the
  view and badge show real data. In the fixture there's no worker heartbeat, so the capacity-wait note reads
  "Worker healthy" (worker-healthy limb unmet) — which is fine and even useful for the screenshot.
- Toggle button visible text is "Eligible" (not "✓ Eligible") so the visual-capture `click "Eligible"` step
  matches by exact accessible name.
