# [Robot] Robot PRs name their ticket: PD-id in the title and a Ticket line atop the body

**What shipped:** `buildTaskPrompt` now stamps `**Ticket:** PD-n — title` as the PR envelope's first
body line and instructs the Robot to end the PR title with `(PD-n)`. The display id is threaded from
`robotQueueCandidates` → `RobotCandidate.displayId` → `session.ts` (with a `#<id>` fallback). The
visual-capture comment now names the PR's own ticket via a new `ticketLabel()` helper instead of the
hardcoded `(PD-773)`/`(PD-798)` build-citations.

**Worth remembering:**
- `linkedTickets` (evaluate/all-prs.ts) needed NO code change — a `robot/t<id>` branch is already
  unmatchable by its branch regex and, with no `(PD-n)` title suffix, it falls back to the first
  display id in the body. The new deterministic `**Ticket:**` line *is* that first id, so linkage
  works via the existing fallback. Only a test was added to prove it.
- Several in-memory test schemas (`select.spec.ts`, `robot.spec.ts`) build a minimal `agent_tickets`
  table; since the candidate SQL now selects `t.display_id`, those CREATE TABLEs needed a
  `display_id TEXT` column or the query errors with "no such column".
