# [bugfix] [Evaluator] A robot/* PR whose ticket is not in-review can never get review-gate

**What shipped:** Made the all-PRs Evaluator path's `robot/*` skip conditional — a `robot/*` PR is
skipped only when its number is a current `inReviewPrTargets(db)` target (the Robot path's own list),
so a hand-finished Robot PR (ticket not in-review) is now reviewed here and a ship opens `review-gate`.
Also removed `review-gate.yml`'s `robot/*` guard so an authorized approval opens the gate on robot/*
branches too, while an unapproved robot/* PR posts nothing (agent-worker still owns its verdict).

**Worth remembering:** `inReviewPrTargets` is the single source for "which PRs the Robot path owns" —
mirroring it directly (a `Set<number>` of PR numbers) keeps the two paths drift-free; do not re-derive
the condition. The all-PRs test DB had to gain `status/assignee/agent_state` columns + the `agent_runs`
table (via `ensureRunsTable`/`startRun`/`finishRun`) to seed in-review targets. Bash tool's cwd
persists between calls — a stray `cd apps/agent-worker` made `npm run verify` resolve the wrong
workspace; run verify from the repo root.
