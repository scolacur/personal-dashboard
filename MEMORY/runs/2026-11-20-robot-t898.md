# [Robot] Keep a run's work when it ends without a hand-off — push WIP before the clone is deleted

**What shipped:** On every non-hand-off exit (no-verify, session error, ask-human) the Robot loop now
commits the clone's WIP (untracked included, gitignored `.robot/` excluded) and force-pushes it to a
dedicated `robot-wip/t<id>` ref before the clone is reused/pruned. The ref+sha are recorded on the
`agent_runs` row and the `robot_fault`/`robot_parked`/`robot_paused`/`robot_ask_human` event, and shown
in a new "WIP" column in RunHistory. The ref is deleted at hand-off (its work is now a PR) and by a
per-cycle terminal sweep for completed/closed/archived tickets. Preserve-only, no auto-resume (D-094).

**Worth remembering:**
- The ticket's Context is stale: it says `robot.ts`'s `finally` removes the worktree on every path. PD-719
  already changed that — the clone is KEPT locally on non-hand-off and reused next dispatch. But reuse does
  `reset --hard HEAD` + `clean -fd`, so *uncommitted* WIP (the PD-721 loss: 2 lint errors left at the
  ceiling, never reached hand-off/commit) is still discarded, and the local clone isn't reachable by a
  human or PD-737 Continue. So the real gap was a *remote* ref, which this adds.
- The loop uses `config.githubReadToken` for its own git (workspace `defaultGitRunner`); pushing needs the
  WRITE token. Refactored workspace's runner into `makeGitRunner(config, token)` and the WIP push uses
  `config.robot.writeToken`. Exported `asOwnerOf` (the `safe.directory` + `-C` wrapper) since the loop (root)
  operates a coding-uid-owned clone.
- `robot-wip/` is a distinct namespace from `robot/` — the `robot/*` globs in robot-auto-merge.yml /
  review-gate.yml / path-guard.yml do NOT match it, and no PR is ever opened from it, so auto-merge can't
  touch it. Verified by reading those workflows.
- Terminal cleanup is largely redundant with hand-off delete (every in-review ticket got there via a
  hand-off that already deleted the ref), but the sweep covers the one real gap: a ticket manually
  closed/completed that NEVER handed off. It nulls `wip_ref` after deleting so it acts once per ticket,
  not every cycle.
