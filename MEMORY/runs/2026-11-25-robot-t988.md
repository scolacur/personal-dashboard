# [Audit] Apply mechanics (field-writes): decision endpoint + Accept archive/complete/reprioritize + Reject+reason + confidence gate + batch

**What shipped:** `POST /audit/findings/:id/decision` + `setFindingDecision` store fn (one txn) that, on Accept, reuses `archiveTicket`/`updateTicket` for archive/complete/reprioritize and flips `decision`; Reject persists `decision_reason` (new column, CREATE + addColumn migration). UI in `AuditReport.svelte`: per-finding Accept/Reject, confidence gate (non-`high` must open ticket first), reprioritize P-level selector pre-filled from the recommendation, reject-reason textarea, and an "Apply accepted" batch over high-confidence archive/complete. Added a visual fixture (`audit-report.ts`) so the report renders in captures.

**Worth remembering:**
- The audit tables were created with `CREATE IF NOT EXISTS` and no migrate step (schema comment says so), but a NEW column on an EXISTING table still needs an `addColumn` migration — the CREATE only helps fresh DBs. Did both.
- `update`-type findings are the blocked sibling slice: the store throws `UPDATE_UNSUPPORTED` on Accept and the UI shows "Accept lands with the update slice" (reject-only). `keep` is non-actionable (no buttons).
- better-sqlite3 nested `db.transaction()` is fine (savepoints) — `setFindingDecision`'s txn wraps `archiveTicket`/`updateTicket`, which have their own.
- The confidence-gate "open to review" link uses `target="_blank"` so clicking it doesn't navigate away and lose the reviewed-state (SPA). Marks the finding reviewed, which enables Accept.
- Visual fixtures run in array order; `audit-report` must sit AFTER `task-tracker` so its findings can point at that fixture's tickets. The existing "never writes into tables that already hold data" spec asserted `['task-tracker']` and needed updating to include `audit-report`.
- Lint forbids plain `Set` in Svelte reactive state — use `SvelteSet` from `svelte/reactivity`.
- Svelte version is `^5.0.0` (ambiguous), so avoided the 5.9+ function-binding form; used `value=` + `onchange` on the select.
