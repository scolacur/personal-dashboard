# [Coder subtypes] Show the area on tickets and agents ("Smith-board #212"), edit it on the Epic page and in Details, and list the areas in the glossary

**What shipped:** Area chips (effectiveCoderArea, marked "(from Epic)" when inherited) on board ticket cards, Epic cards, Epic-member cards and the ticket/Epic detail page; a "Code area" select in the edit modal (null = "Inherit from Epic" on a Ticket, "— None" on an Epic); running Coders now read "Smith-<area> #<runId>" on the Agent Dashboard tiles; the glossary lists the areas under the Coder tab. Label logic is a pure web helper (`devops/coder-area.ts`) with a spec.

**Worth remembering:**
- PD-879 (nicknames / `agent_type_settings`) is NOT merged, so the nickname is a hardcoded `DEFAULT_CODER_NICKNAME='Smith'` constant in `coder-area.ts` (documented default). `coderAgentName` takes an optional nickname arg so the PD-879 value drops straight in later.
- The area helpers live in `apps/web/.../coder-area.ts` (web vitest, since `packages/shared` has no runner). The one shared-package change is `ActiveAgent.coderArea` — it's a REQUIRED field, so the `agent-fleet.spec.ts` ActiveAgent factory needed `coderArea: null` added.
- Server `active-agents.ts` computes the robot run's area via a LEFT JOIN to the ticket's Epic and `effectiveCoderArea`; evaluator/auditor get `coderArea: null`.
- `coderAgentName` uses the raw area id ("board"), not the label ("Board"), per the ticket's "Smith-board #212".
- Gotcha: the detail-page `memberCardSnippet` passes `epic={ticket!}` — `ticket` is `AgentTicket | null` there but members only render for a non-null Epic.
