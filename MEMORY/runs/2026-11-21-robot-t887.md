# [Habit Tracker] Log › By Day grid: lazy 30-day chunks, axis flip, editable cells

**What shipped:** The Log › By Day grid (replacing the PD-725 placeholder in `LogView.svelte`):
items as rows (sets above children, metrics below), habit days as the other axis, today-anchored,
lazy-loading older 30-day chunks via the existing `from`/`to` range endpoints. A **Flip axes**
button swaps rows↔columns (default: days as columns, today rightmost; flipped: days as rows, today
top), remembered per device in localStorage. Habit/set cells tap through the shared outbox (set
cells apply the PD-723 shortcut for that day); metric cells open an inline `MetricInput` popover.
Row-header names deep-link into By Habit. New `?view=day&day=YYYY-MM-DD` deep link scrolls to a day.
Pure logic + tests in `by-day.ts` / `by-day.spec.ts`; the grid component is `ByDayGrid.svelte`.

**Worth remembering:**
- No server work needed — `fetchCompletions(from,to)` / `fetchMetricValues(from,to)` already exist.
  Reused `leafCellState` / `setCellState` / `buildDaySets` / `buildHistoryNode` from `by-habit.ts`.
- Writes go only through `HabitTracker.svelte`'s single outbox: added `setMetricValueOnDay` there
  (day-aware twin of the existing `toggleCompletionOnDay`), passed down as `onMetricWrite`. The grid
  reflects optimistic edits purely by folding the reactive `pending` prop over fetched data — no
  second outbox, no local optimistic mutation needed.
- `svelte/prefer-svelte-reactivity` only flags a `new Map`/`Set` that is **mutated** after
  construction (`.set`/`.delete`). Constructor-form derived maps (`new Map(array)`) are fine; the
  day→element scroll registry had to become a plain `Record` object instead of a mutated `Map`.
- `{@const}` is allowed as the first child of an `{#if}` branch inside a `{#snippet}`, which the
  cell snippet relies on.
- Metric options for choice cells come from `metricRows` (the Today view already carries active
  metrics' options), so the grid needs no extra options fetch.
