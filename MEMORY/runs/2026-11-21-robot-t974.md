# [Auto-queue] [Robot] Circuit breaker: pause dispatch after N consecutive non-retryable failures across tickets

**What shipped:** A loop-wide circuit breaker (D-107) in the agent-worker Robot loop. It counts
consecutive deterministic-tier run failures across DISTINCT tickets in a new `robot_state` slot
(`breaker_consecutive`); at `ROBOT_BREAKER_FAILURES` (default 3) it reuses `pauseDispatch` to pause
the whole loop with a `circuit-breaker`-tokened reason and fires a loop-wide Notification Center
entry naming the failing tickets + signatures. A successful hand-off resets the streak; the
existing `POST …/robot/resume` resets it too (the server's `setDispatchPaused(db, false)` nulls the
key). The nav killswitch summarises the reason as "Circuit breaker tripped"; Site Status shows it
verbatim (already did).

**Worth remembering:**
- A deterministic-tier park and a transient *retry-cap* park are both `action === 'park'` in
  `faults.decideFault`, but only `decision.tier === 'deterministic'` feeds the breaker — the ticket
  is explicit that transient retries don't count. The gate is on tier, not on the action.
- Dedup by ticketId is deliberate ("across distinct tickets"): one flapping ticket re-Unstuck by a
  human must not trip a loop-wide pause on its own (that's the per-ticket retry cap's job).
- The server (apps/server) and worker (apps/agent-worker) are separate builds and do NOT share
  robot_state key constants — they duplicate the literals (`dispatch_paused`, etc.). I followed that
  convention: `breaker_consecutive` is a literal in both `breaker.ts` and `store.ts`, cross-commented.
- The breaker reuses the single `dispatch_paused` flag rather than a 5th halt concept, so the
  existing resume control and Dev Ops readouts work unchanged. See D-107 for why.
