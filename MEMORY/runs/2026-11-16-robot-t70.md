# [Acute Strategies Generator] Draw History — log each Shuffle and show recent draws

**What shipped:** T70. New `asg_draws` store funcs (`recordDraw`, `listDraws`) + routes
`POST/GET /api/widgets/acute-strategies-generator/draws`, shared `AcuteStrategyDraw` type +
`DRAWS_DEFAULT_LIMIT`/`DRAWS_MAX_LIMIT`, client `recordDraw`/`fetchDraws`, and a page-only
`RecentDraws.svelte` section. `shuffle()` logs a draw only when it actually shows an idea;
failures are caught and logged so they never block the draw. Deck mode draws count too.

**Worth remembering:**
- The `asg_draws` table was already hand-written in schema.ts (PR #400) — this ticket only
  builds store/routes/UI on it. Did NOT touch schema.ts.
- Draw is recorded in `shuffle()` after `currentIdea` is set, guarded by `if (currentIdea)`,
  so the auto-pick on load and the filter-change re-pick (which live in `onMount`/`$effect`,
  not `shuffle`) correctly log nothing.
- The limit is clamped in the STORE (`listDraws`), not the route — the route just parses the
  query and passes undefined for a non-numeric value; store clamps [1,200], defaults 20.
- `relativeDrawTime` is a new local pure util (short "3 min ago" form per the ticket), kept in
  the widget's utils.ts rather than reusing lib/job-runs-display's `relativeTime` (longer
  "3 minutes ago" form, and coupling the widget to a job-runs module was undesirable).
- VERIFY FLAKE (pre-existing, unrelated): `apps/server/src/backup.spec.ts >
  "snapshots extra DB paths read-only and survives an unreachable one"` times out at 5000ms
  under full-suite parallel load in this sandbox. Proven NOT mine: it fails identically on a
  clean stashed tree (893 passed) and passes in isolation (~16s). All 17 of my new tests pass;
  build/typecheck/lint green.
