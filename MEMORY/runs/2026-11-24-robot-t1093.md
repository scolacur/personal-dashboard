# [Refine] propose_commit gains a `supersedes` field (existing member ids), validated at propose time

**What shipped:** `RefineProposal.supersedes?: string[]`, a shared `refineSupersedesError(supersedes, mode)`
(mode/malformed/duplicate), `REFINE_PROPOSAL_EVENT.superseded = 'refine_superseded'` which
`latestActionableProposal` now treats as terminating, and in `propose-tool.ts` the zod field +
DESCRIPTION + a board half (`supersedesBoardError`) that rejects ids that aren't an OPEN member of
the target Epic. Approval does not yet consume the field (sibling slice). Specs added in
`propose-tool.spec.ts` cover the shared validator, the board validation, and the terminating event.

**Worth remembering:** The implementation (from the prior run) was complete and verify-green; only
the tests were missing. Two things to know about the board validator: (1) the target Epic is the
target itself when `targetIsEpic` (Populate) else the target ticket's own `epic_id` (plain
decompose), so a non-Epic decompose still has an Epic to supersede members of — and with no Epic in
either case it refuses outright; (2) display ids are matched upper-cased against the DB. The shared
package has NO vitest runner, so shared functions are tested from a consuming app's spec — here
agent-worker's `propose-tool.spec.ts`, mirroring how `board-tools.spec.ts` builds an in-memory DB.
