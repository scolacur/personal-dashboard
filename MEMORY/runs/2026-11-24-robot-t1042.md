# [Coder subtypes] Code-area subtypes: registry, Epic default + per-ticket override, set by Refine

**What shipped:** A `CODER_AREAS` registry + `CoderArea` type + `effectiveCoderArea` resolver in
`packages/shared`; a nullable `coder_area` column on `agent_tickets` (additive migration); write-boundary
validation (`INVALID_CODER_AREA`) on create/PATCH; `approveRefine` writes the area for refine_in_place,
the Epic default on a Populate, and a child's own area only when it overrides; a `coderArea` zod enum +
"always set it" prompt line in Refine's `propose_commit`.

**Worth remembering:**
- This was a continuation. The previous run had finished shared/schema/store/propose-tool but left
  routes + specs + the fixture fallout. Resuming with `npm run verify` first was the right call.
- The real fallout from adding a non-optional `coderArea: CoderArea | null` to `AgentTicket` was in the
  web spec **fixture factories**: each one spreads `Partial<AgentTicket>`, so the missing field surfaced
  as `CoderArea | null | undefined` (not a "missing property" error). Fixed by adding `coderArea: null`
  to 9 devops spec factories. `ticket-form.ts` uses `TicketFormState` (UI, out of scope) so it was left.
- `ValidationError`'s `code` is a string-literal union — a new error code must be added there too, or
  server typecheck fails (it did until `INVALID_CODER_AREA` was added).
- A child's area is stored ONLY when it overrides the Epic (unset → resolved at read time), so
  `approveRefine` passes `coderArea: undefined` (not null) for an unset child to keep inheritance.
- `approveRefine` must stay no-throw, so stored proposals are guarded with `isCoderArea` rather than the
  throwing `validCoderArea`; the propose tool's zod enum is the real propose-time gate.
