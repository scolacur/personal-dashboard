# [Audit] Cross-run reconciliation: sticky findings + dedup + suppression fingerprint (PD-285)

**What shipped:** A `fingerprint` column on `audit_finding` (nullable, server migration + CREATE),
a pure worker module `jobs/audit/reconcile.ts` (`findingFingerprint` + `reconcileDecisions`), and
wiring in `runAuditPass` that reads the most recent prior `done` run's single-ticket findings for
the project and carries each matching decision forward onto the new rows (keyed on
`(ticket_id, type)`, same fingerprint ⇒ carry, changed/absent ⇒ undecided). A `rejected` finding is
suppressed purely by carry-forward; it resurfaces only when its fingerprint changes.

**Worth remembering:**
- The ticket calls the agent-worker writer files `store.ts` / `jobs/audit/`; they're actually
  `apps/agent-worker/src/jobs/audit/audit-db.ts` (+ `audit.ts`). Server read store is
  `apps/server/src/widgets/task-monitor/audit-store.ts`.
- Adding a NON-optional `fingerprint: string | null` to the shared `AuditFinding` silently broke the
  web fixture `apps/web/src/lib/audit-logic.spec.ts` (spread-over-Partial surfaces it as
  `| undefined`, caught only by `svelte-check`, not vitest) — same gotcha the 2026-11-24 PD-880 note
  flagged. Had to add `fingerprint: null` to that factory.
- Deploy-order tolerance (mirrors PD-910): the worker checks `auditFindingHasFingerprint(db)` via
  `PRAGMA table_info` before writing/reading the column, falling back to the pre-fingerprint insert
  (`decision` undecided) so the worker can deploy ahead of the server migration without crashing.
- Fingerprint = sha256 of `JSON.stringify([type, normEvidence, normProposedChange])` (whitespace
  collapsed+trimmed). Used JSON encoding rather than a separator char to dodge field-boundary
  collisions — and because the Write tool turned a literal single-space separator into NUL bytes in
  the source file. Verify green (1080 tests).
