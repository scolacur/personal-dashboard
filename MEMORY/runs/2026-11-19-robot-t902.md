# [bugfix] [Robot] Live turn progress double-counts — one assistant message per content block, not per turn ("119/100")

**What shipped:** `session.ts` live turn counter now counts DISTINCT top-level assistant
`message.id`s (via a `Set`) instead of one per streamed assistant message, since the SDK emits one
assistant message per content block and several per turn share an id. Defensive fallback keeps
id-less messages counting as before. Added two `session.spec.ts` tests.

**Worth remembering:** Budget accounting needs NO separate fix. `updateRunProgress` (the loop's
`onProgress` sink) and `finishRun` write the SAME `agent_runs.turns` column that `budget.ts` sums;
a finished run already carries the authoritative `num_turns`, and in-flight budget reads the live
value — so deduping the live count corrects the in-flight budget view for free. The id lives at
`message.message.id` (the assistant message wraps the Anthropic message object), read defensively
as `unknown`.
