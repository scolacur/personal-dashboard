# [Habit Tracker] Tracer: shared habit store, daily habits on Today (page + card), Habits tab basics

**What shipped:** The first slice of the Habit Tracker (PD-721). A shared habit store in
`apps/server/src/lib/habits.ts` + `habits-routes.ts` (tables `habit_items`, `habit_completions`,
`habit_settings`; routes under `/api/habits`), a `habitDay()` function in `@dashboard/shared`, and
the widget renamed `habit-log` → `habit-tracker` with a Today checklist (card + page) and a Habits
manage tab (add / rename / archive / delete-with-count / native-drag reorder / settings). The
`morning-routine` stub route + registry entry were removed.

**Worth remembering:**
- `habitDay` works on the *local wall clock* (via `Intl.DateTimeFormat`), not by shifting the
  instant, so DST is handled: the one-day step before the boundary is pure UTC calendar math.
  Tested at 03:59→yesterday / 04:00→today and across both DST regimes.
- Stale page membership (`habit-log` / `morning-routine` still seeded into `shell_page_widgets`)
  needs no new code: `resolvePlacements` already drops a placement the registry no longer has.
  Did NOT touch `shell-layout.ts`'s frozen `SEED_PAGES` (it's history, must not edit).
- Lint gotchas on Svelte 5: a `Set` held in state must be `SvelteSet` (`svelte/prefer-svelte-
  reactivity`), and a `$state`+`$effect` mirror of a prop should be a writable `$derived`
  (`svelte/prefer-writable-derived`).
- `completionCount` is derived, so it rides on a separate `HabitItemView` type, not the plain
  `HabitItem` row — the delete confirm names the count with no extra round-trip.
