# [bugfix] [Robot] A worker restart strands in-flight runs for 2h — reclaim orphans by ownership on boot, never by age alone

**What shipped (PD-784, D-104):** The stall reconciler now reclaims by **ownership, not age**. The
live worker keeps an in-memory run registry (`ownership.ts`); a `running` row it does not own was
started by a dead incarnation → reclaimed on the first cycle, no 2h wait. A run it owns is reclaimed
only if its session has hung (no progress past the threshold, measured from the last turn). Process-
restart orphans and graceful SIGTERM interrupts are a new class of **infra fault** (`faults.ts`:
`process-restart-orphan` / `interrupted`): interrupts never count; orphans count only against their own cap + a restart breaker. Added
a SIGTERM drain: the entrypoint aborts in-flight sessions (SDK `abortController`), each closes as a
transient `interrupted` after a time-boxed WIP push, so a boot finds no orphan. `stop_grace_period`
raised to 30s (sensitive path — needs the `sensitive-change-approved` label).

**Worth remembering:**
- Prod runs `ROBOT_CONCURRENCY=1` and sessions are awaited sequentially within a cycle, so at the
  moment `reconcileStalledRuns` runs (cycle start) the live process owns *nothing* — which is why
  the ownership approach is correct for today AND forward-safe for concurrency: an unowned running
  row is always a dead-process orphan.
- `interrupted` (graceful stop) never counts; `process-restart-orphan` (unclean death) counts against
  its own per-ticket cap (`ROBOT_ORPHAN_CAP`, 3) plus a worker-wide restart breaker
  (`restart-breaker.ts`, 4 unclean restarts / 6h → pause). See D-104.
- **`runRobotSession` never throws on an SDK abort** — it catches and returns `{ ok: false }`. The
  first cut handled the interrupt only in the loop's `catch`, so real aborts were classified as
  ordinary faults; its tests passed because the fake session threw. The loop now reads the
  controller's abort reason (`shutdown` | `hung`) on both exits. Fake sessions in tests should
  return the real shape.
- Hung-session detection is still effectively absent at concurrency 1: a hung session blocks the
  cycle, and the reconciler with it. The owned/hung branch only goes live when runs outlive a cycle.
- `startRobotJob` now returns a `RobotLoopHandle` ({shutdown, busy}); the worker entrypoint installs
  one SIGTERM/SIGINT handler that drains the loop then `process.exit(0)`. Only the Robot job drains;
  other jobs are cut off at ≤20s (previously SIGKILLed at 10s) — whether they strand state is unexamined.
- The SDK `query` honours `options.abortController` (confirmed in sdk.d.ts).
