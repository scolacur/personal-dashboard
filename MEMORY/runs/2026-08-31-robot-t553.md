# [bugfix] [task tracker] Mobile sidenav hidden when selecting menu item with children

**What shipped:** Tapping a top-level nav item that has children (e.g. Dev Ops) no longer closes
the mobile drawer — it drills into the sub-panel that slides in within the still-open drawer.
`SideNav.svelte`'s `onParentClick` now only calls `onNavigate()` (which closes the drawer) for
leaf links, gated by a new pure helper `navTapClosesDrawer(hasChildren)` in `nav-utils.ts`
(unit-tested in `nav-utils.spec.ts`).

**Worth remembering:**
- The drawer-close is driven by the layout passing `onNavigate={closeDrawer}` into `SideNav`;
  the fix is entirely in whether the parent link calls that callback.
- Extracted the trivial decision into `nav-utils.ts` because `nav-utils.spec.ts` is a pure-TS
  suite (the web vitest config runs without the Svelte plugin, so component logic can't be tested
  directly there — see the module's existing comment about avoiding `.svelte` imports).
- `npm ci` in this worktree runs with `NODE_ENV=production`, which omits devDependencies (vite,
  vitest). Use `NODE_ENV=development npm ci --include=dev` to get a runnable verify.
- Pre-existing unrelated failure: `apps/server/src/backup.spec.ts > "snapshots extra DB paths
  read-only and survives an unreachable one"` times out at 5000ms. Confirmed it fails on the clean
  tree with my changes stashed — environmental, nothing to do with this nav change.
