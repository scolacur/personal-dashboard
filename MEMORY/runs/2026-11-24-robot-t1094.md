# [Refine] approveRefine closes superseded members + logs refine_superseded, in the approval transaction

**What shipped:** `approveRefine`'s decompose/Populate branch now acts on `p.supersedes`: before the transaction it re-validates each id via a new board-half resolver `resolveSupersedes` (must resolve to a non-archived, open member of the Epic being populated — Epic = the target for a Populate, else the target's own `epic_id`); any failure refuses the whole approval `{ ok:false, reason:'invalid_proposal', detail }` with no writes. Inside the transaction each open member is `updateTicket(... status:'closed')` + `logEvent(... 'refine_superseded', { by: <Epic displayId> })`; already-closed members are skipped (idempotent). Superseded display ids are included in the `refine_committed` detail. New spec `refine-supersedes.spec.ts` covers the PD-837/PD-847 shape, idempotency, and three refusal cases.

**Worth remembering:** This was an infra-interrupted continuation; the prior run had already written the full implementation + spec as uncommitted changes. `npm ci && npm run verify` came back clean (1028 tests), so the work only needed review + hand-off. The shared prerequisites were already on main: `refineSupersedesError` (board-free shape check) and `latestActionableProposal` already treating `refine_superseded` as a terminator — so closing + logging is all that makes a superseded member's own proposal non-actionable. Validation is deliberately split: shape in `packages/shared` (`refineSupersedesError`), board-resolution in the store (`resolveSupersedes`), mirroring the propose-time split.
