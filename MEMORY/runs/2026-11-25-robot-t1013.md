# [Audit] Completion notification: audit_complete kind + fire on actionable run + ticketless link

**What shipped:** New `audit_complete` NotificationKind. The agent-worker audit pass writes one
ticketless `agent_notifications` row (via `notifyAuditComplete` in `audit-db.ts`) when a finished
run has ≥1 actionable finding, collapsing to a single unread. Web `notificationHref` routes
`audit_complete` → `/devops/reports/ticket-audit`, and both the bell dropdown and `/notifications`
now render an `<a>` whenever `notificationHref(n)` is non-null (not just when a ticket is attached).

**Worth remembering:**
- Hoisted the "actionable" denylist from `apps/web/src/lib/audit-logic.ts` into
  `packages/shared` (`NON_ACTIONABLE_FINDING_TYPES` + `isActionableFindingType`) so the worker and
  the web report apply the identical rule; `audit-logic.ts` re-exports it under its old name
  `NON_ACTIONABLE_TYPES` to keep existing consumers/spec untouched.
- Dedup is NOT handled by the server's `createNotification` guard — that only runs for
  ticket-scoped rows, and `audit_complete` is ticketless. Collapse is done explicitly in the
  worker: delete-then-insert over unread rows only (a READ audit_complete is left in history).
- The empty-project early-exit never persists findings and never calls `notifyAuditComplete`, so
  it inserts nothing by construction.
- Svelte 5 `{@const}` must be a direct child of a block, so `{@const href = notificationHref(n)}`
  goes right under `{#each}`, before the `<li>`.
