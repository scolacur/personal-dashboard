# [Audit] Completion notification: audit_complete kind + fire on actionable run + ticketless link

**What shipped:** Resume/rework run — the feature was already implemented on branch `robot/t1013`
and the Evaluator had shipped it (round 1). The PR had gone CONFLICTING against main after PD-838
landed. This run re-integrated `origin/main` and resolved the three audit-file conflicts.

**Worth remembering:**
- The worktree's `origin/main` was fetched at **depth 1** (shallow), so `git merge origin/main`
  died with "refusing to merge unrelated histories" — no common ancestor was visible. Fix:
  `git fetch --unshallow origin main` (recovers the merge base), then merge normally.
- PD-838 refactored the single-project `runAuditPass` into a per-project `auditOneProject` plus a
  new fan-out `runAuditPass` that calls `finishRun` ONCE at the end of the whole run. The
  `notifyAuditComplete(db, run.id)` call therefore belongs after that final `finishRun` in the
  fan-out `runAuditPass` (fires once per run across all projects), NOT inside the per-project
  function — exactly as the Evaluator's advisory noted. The empty-project early-exit returns before
  it, so an empty run still notifies nothing.
- `notifyAuditComplete` reads `audit_finding` by `run_id`, so it is agnostic to the fan-out: it
  counts actionable findings across every project in the run.
