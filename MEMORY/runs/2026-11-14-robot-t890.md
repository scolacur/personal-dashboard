# [Refactor] Lift the Tinnitus offline outbox into apps/web/src/lib/ as a shared module

**What shipped:** A generic offline outbox in `apps/web/src/lib/outbox.ts` (per-key localStorage
persistence, oldest-first flush loop, online/focus/20s retry triggers, pending count). Tinnitus now
binds to it via `createOutbox`, keeping its storage key `tinnitus-tracker:pending`. `queue.ts` is
slimmed to just `PendingEntry` + `newClientId`; the flush/storage tests moved to
`src/lib/outbox.spec.ts`.

**Worth remembering:**
- The outbox mechanics were NOT all in `queue.ts` — the flush orchestration (`flushing` flag,
  snapshot concurrency handling), the retry triggers and the "N pending sync" count all lived
  inline in `apps/web/src/lib/TinnitusTracker.svelte`. `queue.ts` only held the storage + flush loop.
- `apps/web/vitest.config.ts` runs specs with NO Svelte plugin (pure TS) and the default **node**
  environment (no `window`/`document`/jsdom; jsdom/happy-dom are not installed). So the outbox is a
  plain module with an `onChange` callback rather than a `$state`-backed `.svelte.ts` store — the
  component mirrors `onChange` into its own `$state` for reactivity. `start()` guards its DOM wiring
  with `typeof window` so it's testable in node. Recorded as D-093.
- `add()` kicks a fire-and-forget flush, so tests that assert flush outcomes must seed the queue via
  a pre-seeded `kv` + `start()` (not `add()`) to stay deterministic — an `add`-then-await race cost
  a red test.
- `npm run decisions:index` also regenerates `apps/server/src/lib/decision-seed.generated.ts`
  (PD-702 seed floor); commit it alongside DECISIONS.md.
