# [Acute Strategies Generator] Deck Mode — no repeats until the pool has been seen

**What shipped:** A Deck mode toggle on the generator face (both variants). When on, Shuffle
deals the filtered pool like a deck — no idea repeats until the whole current pool has been
seen, then a fresh round starts (never a back-to-back repeat across the boundary when the pool
has >1 idea). Shows "X of Y seen" progress + a Reset deck action. Toggle and seen-set persist
to localStorage. Deck logic is pure functions in a new sibling `deck.ts` with unit tests.

**Worth remembering:**
- `apps/web` vitest runs in the **node** environment (no jsdom) — `localStorage` is undefined
  in tests. The persistence helpers wrap every read/write in try/catch so they work without
  storage; the spec injects a minimal in-memory `localStorage` stub on `globalThis` to test the
  happy path, and deletes it to test the no-storage fallback.
- Test files MUST be `*.spec.ts`, not `*.test.ts` (per the vitest config comment — a `.test.ts`
  is silently never run).
- The seen set is scoped by *idea id*, not pool index, so a filter change keeps already-seen
  ideas seen, and stale ids for deleted ideas are harmless (progress ignores ids not in the
  current pool). Starting a new round clears the whole seen set.
- Deck progress + rollover are driven purely by the seen set threaded forward; the initial
  onMount card and the "current idea fell out of pool" repair both use `pickRandom` and do NOT
  mark seen — only pressing Shuffle in deck mode advances the deck. Intentional, keeps counting
  predictable.
