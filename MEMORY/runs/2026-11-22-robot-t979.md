# [Auto-queue] Epic refined badge shows plan vs members

**What shipped:** A pure shared helper `epicRefinementDisplay(epic, members)` in
`packages/shared/src/task-monitor.ts` returning one of `fully-refined` / `plan-refined` / `stale` /
`not-refined` from an Epic's stored flags plus its OPEN members (terminal excluded). A web mapper
`epicRefinementBadge` in `apps/web/.../epic-members.ts` maps that to a badge (green "Fully refined",
amber "Plan refined · N/M members", unchanged ⚠ Stale, null for not-refined). Wired into the Epic
board card, Epic band (same card) and the Epic detail-page header. New `.refine-plan` amber style.
Fixtures gained a second fully-refined Epic so both card states screenshot.

**Worth remembering:**
- The stored `refined`/`refine_stale` columns are untouched (D-103 settled display-only). Deriving
  the flag was explicitly rejected.
- `packages/shared` has no test runner; its logic is tested from `apps/server` specs
  (`epic-refinement-display.spec.ts` beside `queue-blockers.spec.ts`).
- The EpicCard previously had no `members` prop — added one and pass `membersOf(epic.id, tickets)`
  from the board page.
- Detail header renders the badge only for the two NEW states (fully/plan); stale keeps its
  existing banner (unchanged treatment), not-refined shows nothing. Amber plan badge links to
  `#epic-members` (anchor added to the members section).
