# [Refine] Mark an open question round or pending proposal stale when a ticket it cites changes (PD-889)

**What shipped:** Rounds (`refine_agent` w/ round) and proposals (`refine_proposal`) now carry a
`dependsOn: number[]` (cited ticket ids + the ticket's relations + its Epic), computed by the worker
at ask time (`refineDependsOn` in `refine.ts`, using shared `roundCitedIds`/`proposalCitedIds`). When
a cited ticket goes terminal / split / superseded / body-rewritten / moves Epic, `updateTicket`
fans out one `refine_round_stale` turn to each affected open session. That turn is a Refine-state
event, so it closes the open round (late answers → 409 `ROUND_STALE`), terminates the pending
proposal (`latestActionableProposal`), reads as `refining`, and the worker re-grounds the session
on it with no human action.

**Worth remembering:**
- I hooked the detection ONLY in `updateTicket`, not separately in `approveRefine` as the ticket
  literally says. Every mutation `approveRefine` makes (split-parent close, superseded-member close,
  in-place body rewrite, Populate Epic-body rewrite) already routes through `updateTicket`, so the
  single hook covers all five triggers. The split/superseded verb for the message comes from PD-888's
  `closeReason` set in the same `updateTicket` call (not from the `refine_superseded` event, which is
  logged *after* the close — so a superseded member's stale message says "superseded" without the
  successor name; acceptable, the agent re-reads anyway).
- Debounce is automatic, not a separate check: once a stale turn is newest, `openQuestionRound` →
  null and `latestActionableProposal` → null, so a second change finds nothing to stale.
- `dependsOn` excludes the session's own ticket id — a round must not be staled by edits to the very
  ticket being refined.
- The worker test schema (`refine.spec.ts` `freshDb`) grew `epic_id`/`archived_at` columns and an
  `agent_ticket_relations` table because `refineDependsOn` reads them.
- `task-monitor.ts` now has a value import of `citedIds` from `refine-questions.ts`; no runtime cycle
  because `refine-questions` only type-imports from `task-monitor`.
- Web display of a stale round is PD-941 (out of scope); `refineThreadFromEvents` still drops stale
  turns so the existing thread UI is untouched.
