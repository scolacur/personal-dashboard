# [Habit Tracker] Metrics: Time, Number and multi-select Choice values on Today

**What shipped:** PD-724 metrics — `habit_metric_values` + `habit_choice_options` tables in the
shared store (`apps/server/src/lib/habits.ts`), `setMetricValue`/`setMetricType`/choice-option CRUD,
`PUT /api/habits/metric-values` + `/items/:id/metric-type` + `/items/:id/options` + `/options/:id`
routes, metrics in the server Today view, and the Today Metrics section (`MetricInput.svelte`) plus
metric creation/type/options editing on the Habits tab (`MetricEditor.svelte`). Metric writes ride
the existing shared outbox (PD-729) via the already-present `PendingMetric` message.

**Worth remembering:**
- The write path was pre-built by PD-729: `queue.ts` already had `PendingMetric`, `sendHabitWrite`
  already dispatched to `setMetricValue` → `PUT /api/habits/metric-values`. I built the server route
  to match that exact shape (`{itemId, day, value|null}`), so no second outbox and no API churn.
- Value is always a string on the wire: number as decimal string (`"0"` is a logged zero, distinct
  from `null`/not-logged), time as `"HH:MM"`, choice as a JSON array of option ids. Format validators
  are pure in `@dashboard/shared`; choice option-id membership is checked in the store (needs the DB).
- Type-lock ("can't change once it has values") is enforced server-side by counting
  `habit_metric_values`; the MetricEditor doesn't pre-disable it, it just surfaces the 400 rejection.
- ESLint `svelte/prefer-svelte-reactivity` bans even a transient `new Set(...)` in a `.svelte` file —
  used arrays for the choice selection instead.
- `getTodayView` now returns `{day, rows, metrics}`; existing tests only read `.rows` so nothing broke.
- Rework run: merged `origin/main` (By Habit / completionRate landed meanwhile). Conflicts were all
  additive — `shared/src/index.ts` export lists, and `HabitTracker`/`TodayList` prop lists where my
  `onMetric`/`metrics` and main's `onOpenItem` both needed keeping. The worktree started as a shallow
  clone with `origin/main` at depth 1, so merge-base failed ("unrelated histories") until
  `git fetch --unshallow`.
