# [Evaluator] Non-Robot (all-PRs) path: symmetric one-retry-per-head + full-text diagnostics + terminal-failure notification

**What shipped:** The non-Robot PR path (`all-prs.ts`) now reuses the PD-853 per-lens retry helpers
(`lensStates`/`lensNeedsRun`/`latestLensReport`) keyed on `head_sha`: `headEvaluated` is "every
enabled lens settled (verdict OR one retry used) for this head"; only unsettled lenses re-run and
settled ones fold in from the DB; unparseable replies store the full text (20k cap); a lens that
exhausts its retry raises one `notifyLoop('agent_needs_human', …)` naming the lens + PR.

**Worth remembering:**
- The shared helpers were already on `main` (PD-853 built them); this slice is pure reuse keyed on
  `{prNumber, headSha}`.
- A non-Robot head is a single literal commit, so the per-head verdict cap is **1**
  (`HEAD_VERDICT_ROUNDS`), unlike the Robot path's revise ping-pong that runs one head to `maxRounds`.
  A revise therefore *settles* a head (no re-review); a new push is the next PR-level round.
- `prRounds` had to change from `COUNT(*)` to `COUNT(DISTINCT head_sha)` (and drop its lens arg): with
  retries a head can now have 2 code rows, which would otherwise double-count the round.
- `round` for a retry on the same head must stay the same ordinal — computed as `prRounds` when the
  head already has runs (`priorStates.size > 0`), else `prRounds + 1`.
- The existing `headEvaluated` test in `evaluate.spec.ts` encoded the OLD "any code row = evaluated"
  rule (a single errored row → evaluated); it was rewritten to the new verdict-or-used-retry
  semantics (one error = retry pending = not done).
