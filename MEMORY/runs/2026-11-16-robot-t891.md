# [Habit Tracker] Offline: route ticks and metric writes through the shared outbox

**What shipped:** Habit completion ticks now ride the shared `$lib/outbox` with key
`habit-tracker:pending`, collapsing per `(item, day)` (new generic `collapseKey` option +
`collapseByKey`), optimistic UI, a "N pending sync" line, and pending writes folded over server
state on load so an offline tick doesn't revert. A forward-compatible `setMetricValue` wrapper +
`metric`-kind payload are in place for when metrics land.

**Worth remembering:**
- This branch is off the **tracer slice only** (commit bfc0d03). Metrics, schedules, sets and the
  Log views do NOT exist yet (PD-724/725/726 are future). So only the completion toggle had a live
  UI to route; the metric path (`PendingMetric`, `sendHabitWrite`'s metric branch, `setMetricValue`
  → `PUT /api/habits/metric-values`) is forward infra validated only by unit tests at the collapse
  level, per the ticket's "tested at the outbox/collapse level". The metric endpoint URL/shape is a
  guess grounded in `widgets/habit-tracker/PROJECT.md` §5 and may need aligning when PD-724 lands.
- **Gotcha that cost a cycle:** the outbox's in-flight reconciliation used
  `pending.slice(snapshot.length)` to find entries added during a flush — an append-only assumption
  that `collapseKey` breaks (collapse rewrites the queue's prefix). Fixed by detecting additions by
  object identity (`!inSnapshot.has(e)`) and collapsing the result. Any future outbox feature that
  mutates the queue mid-flight must respect this.
- Collapse only suppresses sends that haven't *started*. The first `add` auto-flushes, so with a
  reachable server the first write is sent before a later collapse can suppress it — correctness is
  preserved anyway because every write is idempotent last-write-wins. The collapse test therefore
  simulates offline during the adds.
- `apps/web/vitest.config.ts` has no `$lib` alias (no SvelteKit plugin); specs under `routes/` must
  import `lib/` by relative path, not `$lib/...`.
