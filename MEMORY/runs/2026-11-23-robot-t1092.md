# [Refine] list_epic_members surfaces which members have an actionable proposal pending (agent grounding)

**What shipped:** `list_epic_members` (`apps/agent-worker/src/jobs/refine/board-tools.ts`) now
returns an `EpicMemberSummary` per member with a `hasActionableProposal` boolean, computed by
reading each member's `agent_ticket_events` (via the read-only `read` guard) and calling the
shared `latestActionableProposal`. The tool description tells the agent to consult the flag and
prefer to supersede/leave alone a member that already has a pending proposal rather than overlap
it (the PD-837/PD-847 collision behind PD-876).

**Worth remembering:**
- Reused the shared predicate `latestActionableProposal` (packages/shared/task-monitor.ts) rather
  than re-encoding "actionable", so it stays correct when the supersede slice adds
  `refine_superseded` to the terminating set — as the ticket required.
- The board-tools spec's in-memory schema had no `agent_ticket_events` table; added it plus an
  `addEvent` helper. Event detail parsing mirrors the server's `rowToTicketEvent`.
- `npm run verify` is red ONLY on `apps/server/src/backup.spec.ts` timeouts — a documented
  environmental flake (5s testTimeout under sandbox load; all 7 pass at `--testTimeout=60000`).
  Unrelated to this change; board-tools build/lint/typecheck/tests all green.
