# [Auto-queue] Server promoter: AUTO_QUEUE=off|dry-run|on with capacity limits and auto_queued audit trail

**What shipped:** The D-103 auto-queue promoter — a Claude-free server interval job
(`auto-queue-promoter.ts`, registered via `task-monitor` `registerCron`, default `* * * * *`) that
pulls eligible Backlog members of active Epics into the Queue in dispatch order, through the SAME
`queueGuardFailure` → `updateTicket({status:'queue'})` path the PATCH route uses. Behind
`AUTO_QUEUE=off|dry-run|on` (default off). Records `auto_queued` / `auto_queue_dry_run` /
`auto_queue_refused` ticket events with the criteria+capacity snapshot, posts one `agent_auto_queued`
Notification digest per promoting tick, publishes a last-tick summary to `robot_state`
(`auto_queue_last_tick`, read via `GET …/auto-queue`), and drives a "🤖 auto-queued" card badge.

**Worth remembering:**
- Most of D-103's backend already existed (PD-808/809/810): `autoQueueEligibility`,
  `computeAutoQueueCapacity`, `getTicketAutoQueueEligibility`. This ticket was the *promoter* +
  audit trail + badge. I refactored `computeAutoQueueCapacity` to build rows via a shared
  `buildAutoQueueCapacity(CapacityInputs)` and read env-configurable limits via `autoQueueLimits()`
  (defaults = the shared `AUTO_QUEUE_*` constants) so board/checklist/promoter can't drift.
- **Capacity is simulated in-memory across a tick, not re-read from the DB per candidate.** That is
  what makes `dry-run` throttle identically to `on` (dry-run writes nothing, so a DB re-read would
  never advance queue-depth / epic-in-flight). The recorded snapshot is built from the same tracked
  counters.
- `queue-depth` / `review-wip` / `worker-healthy` are board-wide **hard stops** (break the tick);
  `epic-in-flight` is **per-Epic** (skip this Epic's ticket, keep going). One-in-flight-per-Epic
  therefore holds across a single tick.
- The guard-refusal branch is **defensive/unreachable in normal flow** — `autoQueueEligibility` is
  strictly stricter than `queueGuardFailure`, so an eligible ticket always passes the guard. Tested
  it by `vi.mock('./ticket-guards')` with a `mockReturnValueOnce` refusal.
- Gotcha that cost time: the `autoQueued` badge subselect lives inside the `LATEST_REFINE_TYPE_SELECT`
  **backtick template literal** — a SQL comment containing backticks (`` `auto_queued` ``) silently
  closed the string. Keep backticks out of SQL embedded in template literals.
- Another gotcha: adding a member to a refined Epic **un-refines it** (sets `refined=0`, not just
  `refine_stale=1`) via D-089 §6 invalidation — test/fixture setup must re-settle the Epic
  (`refined:1`) after each member add, which is why the visual fixture re-marks the Epic repeatedly.
- `@dashboard/shared`'s index uses **explicit named exports**, not `export *` — new shared consts
  (`AUTO_QUEUE_EVENT`, `AUTO_QUEUE_LAST_TICK_KEY`) and types must be added to `index.ts` or they're
  `undefined` at runtime in importers.
