# [Refine] approveRefine refuses a proposal on a closed/completed ticket (terminal guard) + panel says why

**What shipped:** `approveRefine` now refuses with `{ ok:false, reason:'terminal' }` (no writes, no
children) when the ticket is already `completed`/`closed`, checked before any proposal lookup so it
covers every mode (refine_in_place, decompose, Populate). The server approve route maps it to
`409 { code: 'TERMINAL' }`, and the proposal card shows dedicated copy via a new pure helper
`approveFailureMessage` / `TERMINAL_MESSAGE` in `refine-proposal-logic.ts`.

**Worth remembering:**
- `npm run verify` is RED in this sandbox only because of `apps/server/src/backup.spec.ts` — 6
  tests time out at the 5s default doing real SQLite snapshots of large seeded DBs. They pass with
  `--testTimeout=30000`. Pre-existing environmental flake (see MEMORY 2026-11-22), unrelated to
  this change. Every other test (1243) passes.
- The component catch block already surfaced the raw server error, but the ticket asked for a
  testable message map, so the `TERMINAL` code is mapped to friendly copy and other codes fall back
  to the raw message. Had to import `ApiError` into `RefineProposalCard.svelte` to read `e.code`.
- Terminal status is set directly via `createTicket({ status: 'completed' | 'closed' })` in the
  store spec — `coerceStatusOrThrow` accepts terminal lanes, so no post-create update is needed.
