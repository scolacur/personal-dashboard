# [bugfix] [Refine] Record why a ticket closed (close_reason + successors), mark split parents refined, and show it to Refine agents

**What shipped:** A nullable `close_reason` column (`split`|`superseded`|`duplicate`) on `agent_tickets`, exposed as `AgentTicket.closeReason` + a batched-derived `closedInto` (successor display id + title). `approveRefine` now sets `split`/`superseded` + `refined=1` on the tickets it closes; a close with an outgoing `duplicates` relation auto-sets `duplicate`; reopen clears it. An idempotent migration backfills existing closed rows. The Refine board tools' `TicketSummary` now carries `closeReason`/`closedInto`.

**Worth remembering:**
- Migrations live in `apps/server/src/widgets/task-monitor/schema.ts`, NOT `apps/server/src/migrate.ts` (that file is just the `migrate`/`addColumn` framework). The ticket said migrate.ts — it was wrong.
- `closeReason` was made a REQUIRED field on `AgentTicket` (not optional like `backfillExcluded`). That forced adding `closeReason: null` to ~9 web test factories (anchored on `archivedAt: null,`). `closedInto` is optional (list/get only).
- `closedInto` is computed in two batched queries in the store (`closedIntoByTicket`): one over relations (split/duplicate, matched to the row's reason), one over `refine_superseded` events joined `agent_tickets.display_id = json_extract(detail,'$.by')`. The board tools recompute per-row (capped result sets, no N+1).
- A superseded `by` recorded as a bare numeric id (parent without a displayId) won't resolve a successor row — the reason still shows, link doesn't. Acceptable per ticket.
- Touches `schema.ts` + `apps/agent-worker/**` (both sensitive paths) → PR needs the `sensitive-change-approved` label to go green.
