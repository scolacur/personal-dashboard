# [Refine] Show a stale question round or proposal greyed out with its reason; explain the ROUND_STALE refusal

**What shipped:** The web half of PD-889. A new pure helper `apps/web/src/lib/refine-stale-logic.ts`
(+ spec) exposes the stale-detection rule (`latestRefineStale` — newest Refine-state event is a
`refine_round_stale`), the one-line reason copy (`staleReasonText`), the stale proposal to show
greyed (`staleProposal`), and the inbox's `ROUND_STALE` copy (`answerFailureMessage`). `TicketThread`
now renders a greyed, unanswerable stale round/proposal with its reason and a re-grounding cue;
`RefineProposalCard` gained a read-only `stale` mode. The Decisions inbox catches a `409 ROUND_STALE`
on submit, shows the reason at page level, and refreshes so the now-stale item drops.

**Worth remembering:**
- `refineThreadFromEvents` drops `refine_round_stale` (only projects human/agent turns), and
  `latestActionableProposal` returns null once a stale turn is newest. So the thread had NO signal a
  round/proposal went stale — it would keep showing the open round as answerable. The fix reads the
  raw events in `TicketThread.load()` through the new helper, and finds the stale proposal via the
  newest `refine_proposal` event (not the actionable one, which is gone).
- The stale state is transient (worker re-grounds and posts a new agent turn, clearing it), so it
  reads as `refining`, and `awaitingAgent` stays false (last message is an agent turn) — no double
  working indicator.
- `RefineRoundStaleDetail` carries only `changedDisplayId`/`change`/`invalidates` — no split-target
  ids/titles — so the reason copy is built from those three; the ticket's richer example is
  illustrative.
- Added a stale-round fixture to `visual-fixtures/task-tracker.ts` so the thread UI is photographable;
  the stale event must be written AFTER the agent round so it's newest.
