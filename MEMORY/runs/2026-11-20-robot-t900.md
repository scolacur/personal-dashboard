# [Task Tracker] Status pill opens a "needs you" modal

**What shipped:** Clicking the Robot status pill on a `stuck` / `awaiting-human` / `needs-human`
ticket now opens `StatusActionModal.svelte` on the board (no navigation): it shows the state
description + park/fault reason, the agent's own words (ask_human question inline, output tail
collapsed), run count + cumulative turns, the per-state actions (Unstick/Reset, inline answer box,
Open PR link), and a link to the detail page. Per-state content is a registry in a pure
`status-action.ts` module with vitest coverage.

**Worth remembering:**
- The ticket names `task-tracker/TicketCard.svelte`, but the real card is
  `apps/web/src/routes/devops/TicketCard.svelte`. The pill's click goes through `onOpenStatusLegend`
  on the board `+page.svelte`, not the card.
- PD-619 is NOT yet merged in this branch — the pill currently opens the robot-status **glossary**
  for all states, not the detail page the ticket describes. I branched the existing
  `onOpenStatusLegend` callback: input-needed states → modal, everything else → the glossary it
  already opened. Expect a small merge touch-up against PD-619 at that one callback.
- `apps/web/vitest.config.ts` only runs `.spec.ts` and has NO svelte plugin, so `.svelte` files
  can't be unit-tested. The registry + all content-derivation (parkReason/askQuestion/
  buildStatusContent) live in pure `status-action.ts` for that reason; the modal is a thin renderer.
- `checkpoint` (PD-737) deliberately slots in as one more registry entry (commented placeholder);
  its `status-report` words source + Continue/Restart are out of scope here.
- No "won't fix" server route exists today, so needs-human offers Open PR + Reset and relies on the
  "Open full ticket" link for anything else, per the ticket's "otherwise just link".
