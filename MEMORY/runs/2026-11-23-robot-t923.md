# [Evaluator] Raise the review round cap from 2 to 5 once rounds are cheap

**What shipped:** Made the Evaluator round cap configurable via `EVALUATOR_MAX_ROUNDS`
(`EvaluatorConfig.maxRounds`, default 2). Both review paths (Robot `evaluate.ts` and all-PRs
`all-prs.ts`, including the "up to N rounds" PR comment text) now read the configured value;
`MAX_EVALUATION_ROUNDS = 2` in `verdict.ts` is kept only as the default. Production value unchanged.

**Worth remembering:**
- `gateForOutcome(report, round, maxRounds)` in `review-gate.ts` already took `maxRounds` as a
  parameter, so the review-gate path needed no signature change — only the two callers that were
  passing the constant.
- `config.ts` now imports `MAX_EVALUATION_ROUNDS` from `jobs/evaluate/verdict.ts` (for the default)
  and `logger` (for the invalid-value warning). No import cycle: `verdict.ts` imports only
  `@dashboard/shared`.
- `verdictComment` in `all-prs.ts` is a pure standalone export with no `config`, so it gained a
  `maxRounds` param rather than reaching for config.
- The Evaluator env vars are documented in `config.ts` interface doc comments only — they are NOT in
  `ops/agent-worker/agent-worker.env.example`, so that is where `EVALUATOR_MAX_ROUNDS` is documented.
