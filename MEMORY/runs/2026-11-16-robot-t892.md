# [Acute Strategies Generator] IdeaEditModal leaves `saving` true after a single Save (latent; from Evaluator advisory)

**What shipped:** In `IdeaEditModal.svelte`, the single-Save success branch now resets `saving = false` before calling `onCancel()`, so the modal's disabled state no longer depends on the parent unmounting it. The "Save and add another" and failure paths already reset it.

**Worth remembering:** The `saving` flag is pure component ($state) state — it cannot move to `utils.ts`, and `apps/web` has no component tests, so (per the ticket) no test was added. One gotcha: the full `npm run verify` has a flaky server test (`src/backup.spec.ts > snapshots extra DB paths...`) that times out at 5s under parallel load but passes in isolation (~16s) and on retry — unrelated to this web-only change.
