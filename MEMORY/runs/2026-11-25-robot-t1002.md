# [Audit] Projects page: list + Include-in-Audit toggle + create-project (prefix + repo)

**What shipped:** A `/devops/projects` route (list of projects with name/prefix/repo + an
"Include in Audit" checkbox bound to `auditEnabled`, PATCHed optimistically) and a New Project
form (name, prefix, repo). Server: `PATCH /projects/:id` + `updateProject` in `store.ts`;
`createProject` + `POST /projects` now persist/require `key` (prefix) and require `githubRepo`.
Nav link added to `pages.ts` (Dev Ops side nav) and the Task Tracker board toolbar.

**Worth remembering:**
- `agent_projects` already had the `key`/`seq` columns (added in slice 1's migration
  `agent_projects_add_key_seq`); `createProject` just wasn't inserting `key`. `nextDisplayId`
  falls back to prefix `'T'` when `key` is null.
- The create form asks for name/prefix/repo but the `slug` column is NOT NULL UNIQUE, so the
  frontend derives `slug` from the name (`slugify` in `projects-form.ts`); a collision surfaces
  as the server's existing `409 DUPLICATE_SLUG`.
- eslint rule `svelte/prefer-svelte-reactivity` rejects a plain `new Set()` held in `$state` —
  use `SvelteSet` from `svelte/reactivity` (bit me on the saving-in-flight set).
- Projects page is non-empty under visual fixtures because `bootstrapSchema` seeds 3 projects.
