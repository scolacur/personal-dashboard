# [Habit Tracker] Log › By Habit calendar: week rows, month gutter, streak stats

**What shipped:** PD-726 — the Log tab's **By Habit** calendar: a dropdown of items (tree order +
Archived group), a grid of habit weeks (Mon–Sun, newest at the bottom, scroll-up lazy-loads one
earlier week at a time, month names in a left gutter), tap-to-toggle cells (done/extra/due/not-due,
sets derived), and header stats (current/longest streak + completion rate over the last 30 due
periods). Added a `LogView` container with a By Day / By Habit switch (By Day is still a PD-725
placeholder) and the `?view=habit&item=<id>` deep link. New shared pure functions
(`completionRate`, `setCompletionRate`, `habitMonthSpans`, `habitWeeksEndingAt`) are tested in the
server suite; the client helpers in `by-habit.ts` are tested in the web suite. See D-102.

**Worth remembering:**
- **By Day (PD-725) does not exist yet** and **the metric value store (PD-724) does not exist** —
  there is no `habit_metric_values` table/route; `setMetricValue` in `api.ts` targets a route that
  404s. So metrics appear in the dropdown but show no stats and inert (blank) cells here. If you're
  picking up PD-724/PD-725, the Log container (`LogView.svelte`) and the deep link already exist.
- **The Today row is a single tap-to-tick `<button>`** (PD-721/723). The ticket said "tap the name"
  to open By Habit, but nesting a nav button inside the tick button is impossible and splitting the
  row shrinks the tick target. So the calendar opens from a dedicated 📅 control beside each page
  row (not the card), navigating to the deep link. Recorded in D-102.
- **Completion rate semantics** (D-102): same period model as the streak functions (due days, or
  weeks for per-week), floored at the earliest completion, current in-progress period excluded. This
  keeps the header's rate and streak consistent.
- **Completions are fetched once over `('2000-01-01', today)`** because the 2025 import (PD-694)
  writes completions predating `createdAt`, so you can't floor the fetch at creation. Toggles mutate
  the loaded list optimistically; the durable write rides the one shared outbox owned by
  `HabitTracker.svelte` (never the write API directly).
- A `{' '}`-style indent in a Svelte `<option>` landed as a literal non-breaking space (U+00A0) in
  the source; the Edit tool wouldn't match it as an ASCII space. Watch for nbsp if an Edit mysteriously
  "can't find" a string.
