# [Habit Tracker] Completion feedback layers + yesterday banner

**What shipped:** The Today completion-feedback layers (spring-fill on tick, set-complete pulse on
row+chip, once-per-habit-day whole-day burst, streak-milestone flourish) and the dismissible
"Yesterday: N habits unchecked" banner that deep-links to Log › By Day at yesterday. All animations
are pure CSS/transitions, respect `prefers-reduced-motion`, no new deps.

**Worth remembering:**
- Testable logic went into two pure web-local modules with specs: `completion-feedback.ts`
  (`isDayComplete`, `shouldFireDayBurst`, `isStreakMilestone`) and `yesterday.ts`
  (`uncheckedYesterdayCount`). The burst "no replay after untick+re-tick" rule is `shouldFireDayBurst`
  gated on a persisted `lastBurstDay` (localStorage `habit-tracker:burst-day`).
- ESLint rule `svelte/prefer-svelte-reactivity` flags any *mutated* `new Map`/`new Set` inside a
  `.svelte` file (even non-reactive local ones). Fix: build the per-item maps inside a `.ts` module
  (yesterday.ts takes raw arrays), and use plain `Record<>` objects for TodayList's cross-render
  `prevDone`/`prevStreak` tracking. Reactive transient sets (`justTicked` etc.) stay `SvelteSet`.
- Animation layers fire only on real transitions (diff current tree vs previous render) so nothing
  animates on load or on a no-op re-pull. Streak flourish fires when the server-computed streak
  refreshes after a tick syncs (D-095) — slightly delayed, which is fine.
- The yesterday deep link (`?view=day&day=<YYYY-MM-DD>`) was already wired in HabitTracker.svelte
  from PD-725; I just added the banner that uses it. `openYesterday()` uses an absolute goto so it
  works from the dashboard card too.
- Extended the visual fixture with a daily "Floss" habit left unchecked yesterday, otherwise the
  fixture completed every due habit yesterday and the banner would never render in screenshots.
