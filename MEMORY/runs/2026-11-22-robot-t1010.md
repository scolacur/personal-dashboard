# [Robot] Loop toggle shows "worker offline" when the agent-worker heartbeat is stale

**What shipped:** `describeDispatch` in `dispatch-killswitch-utils.ts` now reads the `agent-worker`
heartbeat from `status.workers` and sets `workerOffline`/`workerLastSeen` on every `DispatchView`
branch, judged by the shared `AGENT_WORKER_HEARTBEAT_STALE_MS` (90s). New pure helpers
`loopStateLabel` (→ "On · worker offline" / "Off · worker offline") and `workerOfflineDetail`
(→ "Worker last seen 4m ago — nothing is running"). The nav `DispatchKillswitch.svelte` shows the
suffix on the on/off state and a warn-coloured line linking to `/devops/agent-dashboard` (System
Status). The pause/resume action is untouched — the toggle still records intent while offline.

**Worth remembering:**
- System Status lives at route `/devops/agent-dashboard` (SystemStatus.svelte is mounted there),
  not a `/devops/system-status` path — the component filename is misleading.
- `SystemStatus.svelte` defines its own local `STALE_MS = 90_000` rather than importing the shared
  constant; the ticket asked to use the shared one, so I imported `AGENT_WORKER_HEARTBEAT_STALE_MS`
  rather than copy its literal. Left SystemStatus's copy alone (out of scope).
- `formatRelativeTime` lives in `./deploy-status-utils`, reused for the last-seen age.
